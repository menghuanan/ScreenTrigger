# 产品定义

## 产品是什么

ScreenTrigger 是运行于 Windows 10/11 x64 的本地桌面视觉自动化工具。所有应用窗口与交互采用原生 WinUI 3。它把“目标样本 → 识别条件 → 识别结果 → Lua 动作”连接成可停止、可调试的执行过程；识图是可选能力，纯键鼠脚本也可运行。

## 问题、用户和价值

| 目标用户 | 当前问题 | 产品提供的结果 |
|---|---|---|
| 有基础脚本能力的办公用户 | 重复点击、等待界面、人工抄读文字 | 本地识别界面状态后执行重复任务 |
| 桌面测试人员 | 没有稳定控件 API 的界面难以验证 | 以图像、颜色和文字条件驱动测试步骤 |
| 个人效率工具用户 | 固定坐标宏易在界面变化时点错 | 用目标编号和识别结果定位，并限制操作范围 |

典型任务：看到“完成”文字后继续下一步；读取屏幕上的数值交给子脚本计算；在某应用客户区内循环操作；只监控区域，未命中时等待，超时后提示或停止。

首版不是零学习成本的 RPA 平台。用户需要会选目标、设置阈值和写少量 Lua。上传图片指导入本地文件，不表示上传至互联网。

## 发布边界

首版承诺范围包括：实时框选预览、默认主窗口所在显示器、10×10 物理像素下限、坐标尺寸显示、主窗口瞬间隐藏/自动恢复；图片目标与分组；模板及轮廓、颜色、多语言离线 OCR；复合条件；Lua 互调与调试；区域监控；选择已打开的应用窗口；键鼠输入和临时区域约束；全局快捷键；普通运行隐藏实时日志面板。

MVP 只是内部联调里程碑，不代表删去首版要求。窗口绑定、互调、调试等必须在首版发布门槛前完成。见[任务依赖与验收入口](../agent/任务拆解.md)。

明确不做：

- macOS/Linux 首发、云端 OCR/API 服务、联网同步、远程控制。
- 给脚本开放任意文件、网络、系统命令；第三方恶意脚本防护沙箱。
- 全语言/所有 Unicode 符号百分百识别保证；不支持的模型覆盖必须可见。
- 保存或复用工作区/监控区域；重开应用需重新选择区域及窗口。
- 后台、最小化或被遮挡窗口的可靠输入与完整截图保证。
- 插件市场/热安装任意代码、无代码流程编辑器、默认 GPU、首版 SQLite 切换。
- 同时在多个应用进行互相抢占的键鼠自动化；首版最多三个活动根执行，Rust 为每根维护租约并串行派发输入。

## 成功标准

以下是建议的发布验收门槛，不是已测性能；测量方法和固定环境见[验收与测试](../agent/验收与测试.md)。

| ID | 标准 | 证据 |
|---|---|---|
| S01 | 两类路径完整：纯脚本；框选/导入 → 目标 → 识别 → 脚本动作 | TEST-001、TEST-003、TEST-004、TEST-007、TEST-011 的端到端记录 |
| S02 | 每个成功匹配返回稳定 target_id、样本号 sample_no、坐标和条件证据 | TEST-004，重命名和重启后 ID 不变 |
| S03 | 受限区域、失焦、停止均不会继续派发不允许的输入 | TEST-005、TEST-006、TEST-008，输入事件审计无违规记录 |
| S04 | Lua 断点/单步可查变量；JSON 子脚本参数与返回可往返 | TEST-009、TEST-010，错误调用栈可定位 |
| S05 | 保存中断不会把已有有效数据覆盖成空数据 | TEST-012，故障注入及校验报告 |
| S06 | 普通运行不弹实时日志窗口；可见状态与停止入口始终存在 | TEST-007、TEST-013，人工交互验收 |
| S07 | 离线运行无必需网络请求；OCR 覆盖列表与实际模型一致 | TEST-002、TEST-014，本地介质、包内依赖、进程树网络记录和缺模型实测 |
| S08 | 模板/轮廓固定数据集 precision ≥0.95、recall ≥0.90；中、英、日 OCR 各自 CER ≤10%，韩语 CER ≤11.56% | TEST-004；按各语言编辑错误数与参考字符数的精确比值判定 |
| S09 | 指定测试环境下框选预览 p95 ≤200ms；1Hz 模板监控无积压；停止立即关闭输入闸门，p95 ≤200ms | TEST-001、TEST-008、TEST-015；不可中断推理允许稍后清理，但不得发新输入 |

没有用户研究、模型基准或依赖探针结果时，不宣称“美观易用已验证”“全语言已实现”“安装包仅数 MB”。发布前还需由产品负责人确认用户体验、模型覆盖和建议默认值。
