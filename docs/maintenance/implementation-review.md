## 修补与复验顺序

人日按一位熟悉该项目的工程师每天 8 小时估算。假设可使用当前模型、授权本地数据、测试窗口和工作区；用户指定移除的两项环境占用 **0 人日**。不计产品负责人排队时间。表内工时包含修改及所属回归。

**历史证据已做第一轮去重。** 117 份异常回执合计有 216 次不匹配引用，涉及 31 个路径、39 份不同版本。比对 310 个候选文件、5 个历史 ZIP 和 683 个可达 Git blob 后，20 份已定位到 SHA-256 完全匹配的原字节，19 份在该范围内未找到。74 份回执的异常引用均有历史原件线索，其余 43 份至少缺一份。逐项位置、哈希和关联回执见本地 `reports/raw/closeout-20261126/history-original-inventory.json`。优先向旧工作区和备份按这 19 个哈希查找。对审核器仍按原位置验真的旧源码引用，要保留实际溯源链，覆盖当前源码会破坏现行实现。

本工期覆盖查找、修补和复验。新测试只能证明当前版本的行为。正式放行日期还取决于缺失原件能否找回、已找到的历史原件能否按规则核验，或负责人另行授权的历史处置。首次优化若仍不能使韩语达到约定质量，须按新的实测重新估算。
