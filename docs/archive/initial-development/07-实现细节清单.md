# 实现细节与技术探针

本页提供算法边界和探针清单，替代原稿中未经运行验证、互相冲突的“直接复制”实现。现有业务代码可供对照。WinUI 3、Windows App SDK、PaddleOCR 和 Lupa 的精确组合按 P0 探针验证并锁定。

## 1. Windows / DPI / 捕获

- 进程创建窗口之前启用 Per-Monitor V2 DPI awareness，并验证 XAML 局部 DIP、窗口实际缩放、Rust 和 Python 捕获库返回的单位。不要重复把已物理化坐标乘缩放。
- 覆盖层只建在选定显示器；UI 局部 DIP 转换时使用该窗口客户区的物理屏幕原点和当前 XamlRoot.RasterizationScale。反向拖动先归一化，边缘左右取 floor/ceil 避免少一列像素。
- 窗口客户区用真实 ClientToScreen/屏幕坐标转换；不能用包括标题栏的 GetWindowRect 原点代替。
- 捕获后端建议先评估 Windows Graphics Capture 的桌面/窗口路径及排除覆盖层能力，保存每个 OS 版本的探针记录；Python 可通过适配器消费 Host 帧。若采用其他库，必须证明同样实时、干净、DPI 正确，不仅返回一张静态截图。
- 主窗口隐藏完成后才开始捕获；保存原显示状态，在成功/取消/异常统一 finally 中恢复。选区预览用最新帧有界缓冲，不把一秒前截图作为实时画面。

以下仅展示纯坐标运算，可单独验证；不能替代 Win32/覆盖层端到端测试。

```python
from math import floor, ceil

def local_dip_rect_to_physical(a, b, origin, scale):
    if scale <= 0:
        raise ValueError("scale must be positive")
    left = origin[0] + floor(min(a[0], b[0]) * scale)
    top = origin[1] + floor(min(a[1], b[1]) * scale)
    right = origin[0] + ceil(max(a[0], b[0]) * scale)
    bottom = origin[1] + ceil(max(a[1], b[1]) * scale)
    return {"x": left, "y": top, "width": right-left, "height": bottom-top}
```

## 2. 识别与模型适配

P0 必须分别记录 Python、paddleocr 包、paddlepaddle/其他候选推理运行时、模型 family/version、语言包、OpenCV、CPU/GPU、Win10/11 架构。不要把 PP-OCR 模型名称当 Python 包版本，也不要写一个 lang='ch' 就声称所有语言。

OCRProvider.initialize 只加载显式已安装模型路径，禁用隐式联网下载；模型缺失让能力标 unavailable。先测空图/无字/低分/旋转/多行结果形状，再写解析适配器。供应商异常归一为 MODEL_UNAVAILABLE/RECOGNITION_FAILED；原始 traceback 留诊断，不混入 stdout。

OCR 显式本地加载（TASK-015 探针 venv 实测）：构造引擎须**同时**传检测与识别的 `model_name` 与 `model_dir`（仅传 `model_dir` 会与默认模型名不匹配而报错）；固定 `enable_mkldnn=False` 规避 PIR/onednn 崩溃（`paddlepaddle 3.3.1`，mkl=ON）；`predict` 接受 BGR `ndarray`。模型元数据（逐文件 sha256 + 许可证 + 语言）由仓内 `manifest/models.catalog.json` 提供，权重二进制留在权重库根（**不联网、不入仓库**）；能力披露 `capabilities[ocr].reason` 的固定规范格式见 03。

模板候选：尺寸和方差校验 → 可选尺度枚举 → TM_CCOEFF_NORMED → 阈值 → NMS → 100候选上限。轮廓：统一灰度预处理 → 固定 Canny 参数 → 外轮廓 min_area → Hu moments / matchShapes I1 → 归一分数；用纹理变色但形状不变的夹具证明它与模板能力不同。该算法候选必须经真实样本验证，失败时调整 Provider，不能改变阈值含义而不更新版本。

颜色：统一 BGR/RGB 转换，HSV 对 H 做环绕距离；连通域候选避免把所有分散红像素包成一个巨大框。复合条件在同帧候选局部 ROI 上执行，保留每叶 evidence；置信度与实际精度分别报告。

缓存只减少计算，不使输入跳过新帧或新窗口几何验证。缓存键含 source hash、模型/算法版本、条件 revision、region、geometry_revision；负结果也需正确失效。帧登记（会话图像注册表随像素一并登记 `space/origin/geometry_revision/binding_id/captured_at/frame_id`）使 `image_id → Frame` 可真实还原 ⇒ `geometry_revision`/`space` 为真实值，新窗口几何或新帧必产生新键（旧结果永不用于新几何）；`match_*` 另把**模板内容 sha256** 折入缓存参数，模板内容变必 miss。

## 3. Lua VM 与取消

显式选择并验证 Lua 5.4 构建，例如候选 `lupa.lua54`，启动探针读取 `_VERSION`；不得默认假设 `from lupa import LuaRuntime` 就一定为 5.4。包的桥接关闭参数、allocator 限额须按锁版本验证。

宿主预先保留 debug.sethook/getinfo/getlocal 等私有引用，把用户 chunk 绑定到全新 `_ENV`，不让用户 environment 修改 hooks。line hook 支持断点，call/return hook 维护调用深度，count hook 周期检查取消，避免 `while true do end` 永远占用。count 间隔从 10000 指令评估，不承诺固定耗时。

宿主函数装饰器每次调用前后检查取消/暂停/根期限；wait 使用最多50ms切片或通知等待，不 sleep 整段时长。停止先由 Rust 关闭输入，因此 Python worker 阻塞也不能继续操作。不可中断原生调用位于可终止 worker；线程 Future.cancel 不代表已运行的本地库被取消。

Lua table→JSON 显式区分数组/对象/null，遍历记录 visited 与深度/大小，拒绝函数、userdata、混合键和 NaN。不能 `isinstance(value, lupa.lua_type('table'))`；先通过已验证的 runtime type API 判断值。禁止把 Python exception/object 原样交回 Lua 供反射访问。

## 4. IPC 与进程管理

Rust 管理 release sidecar 的绝对应用资源路径，不依赖用户 PATH 上的 python。开发时可显式使用隔离 venv；参数数组启动，不拼接 shell 命令。Windows 隐藏控制台；进程树加入可清理的 Job Object 或等效受验证机制，退出不遗留 OCR/Lua worker。

双向协议使用独立 reader、单 writer 和 pending-map；response 按 ID 关联，host_request 不进入 UI 命令路由。stderr 也必须持续 drain，避免日志填满管道后死锁。异步执行先返回 ID 再出事件。大图片由 ImageStore 保留，预览只发小图；frame 释放和拥有权必须可测。

C# 通过版本化 C ABI 访问 Rust 注册的命令和原生窗口服务。文件选择器只交付会话令牌，视图只消费引擎提供的结果。此处是应用接口边界，并不是补建用户拒绝的脚本安全沙箱。

## 5. 输入与热键

SendInput 在 Rust 中串行派发；窗口前台与身份、租约、当前区域、geometry_revision、stop 标志都通过后才发 OS 事件。绝对鼠标坐标归一化须使用虚拟屏幕起点/尺寸和 VIRTUALDESK 标志，并在混合 DPI 负坐标环境验点；不得按主屏宽高单独换算。

Unicode 文本以 UTF-16 单元验证补充平面字符/代理对；不能把 pyautogui.write 当成全 Unicode 输入。组合键在 finally 逆序释放账本里持有键。长移动/拖拽逐采样检查取消，部分已派发动作不自动重试。

全局快捷键用 Rust 独立消息线程的 Win32 注册机制；操作系统返回冲突才算冲突检测，不能仅比对几组保留字符串。热键更新先申请新组合，成功落盘后注销旧组合；若保存失败撤销新组合并保留旧组合。停止命令直接关闸门，不依赖 UI 或 Lua hook 先响应。

## 6. 数据保存与迁移

按照 02 generation 提交协议，不能每次保存各 new 一个局部 Lock 冒充全局互斥，也不能把5分钟自动保存作为用户点击“保存”的成功依据。用户明确保存必须完成 durable commit；自动保存编辑草稿可另做非权威缓存。

原子替换只保证同卷单文件可见性，不能直接保证图片+targets+groups 一起事务化；因此使用不可变资产/generation 和 current 指针。flush/fsync/Windows replace 失败必须可注入，测试进程在每一步被终止后仍能加载一个一致版本。不要使用 string.startswith 验证路径包含关系，应解析规范路径并做路径组件关系判断，额外拒绝链接逃逸。

JSON→SQLite 后续迁移记录 schema、计数、内容 hash，验证过后切换；已有新数据库写入时禁止直接用旧 JSON 覆盖回滚。
