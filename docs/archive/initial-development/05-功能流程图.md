# 状态机与关键时序

此处为产品 F01–F08 的实现视图；状态字符串以 02 为准。任何实现都必须覆盖失败和取消分支，不能只照成功线写代码。

## 根执行状态

```mermaid
stateDiagram-v2
    [*] --> starting
    starting --> running: 校验通过 / 租约可用
    starting --> failed: 初始化失败
    starting --> stopping: 停止
    running --> paused: 用户暂停 / 窗口失焦
    running --> debug_paused: 断点 / 单步完成
    paused --> running: 用户继续且上下文有效
    debug_paused --> running: 继续 / 单步
    running --> completed: 返回 / 轮次完成 / 停止目标命中
    running --> failed: 未处理错误 / 超时
    paused --> failed: 窗口关闭
    debug_paused --> failed: 窗口关闭
    running --> stopping: 用户停止
    paused --> stopping: 用户停止
    debug_paused --> stopping: 用户停止
    stopping --> cancelled: 输入已关闭且清理完成
    completed --> [*]
    cancelled --> [*]
    failed --> [*]
```

完成/失败/取消都先执行输入清理再发布终态。输入闸门的关闭早于耗时资源清理。until_target 命中终态 completed(reason=target_detected)；手动/脚本 stop 终态 cancelled；等待策略 stop 到期为 failed(reason=timeout)。若停止与成功同时到达，由 controller 的单一事件队列决定先接受者，已进入 stopping 不再接受完成结果，终态只发一次。

paused/debug_paused 不继续计根执行期限。恢复时重新验证窗口/区域；未满足仍保持暂停。只有 debug_paused 支持单步，普通暂停可继续或停止。stopping 拒绝 pause/resume/新输入，重复 stop 返回相同状态。

## 启动与退出

```mermaid
sequenceDiagram
    participant UI as WinUI 3
    participant Host as Rust 原生宿主
    participant Engine as Python Engine
    participant Store as Repository
    UI->>Host: 初始化原生宿主并请求启动
    Host->>Engine: 启动受管理进程树 + session_id
    Host->>Engine: hello
    Engine->>Store: 获取写锁 / 校验当前 generation
    Store-->>Engine: 一致数据或恢复错误
    Engine-->>Host: 版本 / 能力 / 模型状态
    Host->>Host: 注册全局停止入口
    Host-->>UI: system_ready + 可用能力
    UI->>Host: 退出
    Host->>Host: 关闭输入闸门 / 释放持有按键
    Host->>Engine: 停止全部执行并关闭
    Engine->>Store: 完成已提交写入 / 释放锁
    Engine-->>Host: 退出
    Host->>Host: 清理子进程 / 注销热键
```

协议不匹配则拒绝运行；OCR 缺模型仅影响 OCR。启动 30s 超时展示重试/诊断，不能显示“已就绪”。引擎异常退出也执行 Host 清理；应用退出最多等待 2s 工作任务清理，超时终止 worker，未提交数据保持旧 generation。

## 框选

```mermaid
sequenceDiagram
    participant User as 用户
    participant UI as WinUI 主窗与覆盖层
    participant Host as Rust 宿主
    participant Capture
    User->>UI: 开始框选
    UI->>Host: start_selection_mode
    Host->>Host: 暂停输入并记录窗口可见状态
    Host->>UI: 请求隐藏主窗并打开原生覆盖层
    UI-->>Host: 确认可见性与覆盖层就绪
    Host->>Capture: 干净桌面实时帧
    loop 拖动期间
        Capture-->>Host: 最新选区帧
        Host-->>UI: 预览引用
        UI-->>User: 物理坐标 / 尺寸 / 预览
    end
    alt 确认合法区域
        User->>UI: 确认选区
        UI->>Host: confirm_selection
        Host->>Capture: 获取最终无覆盖层帧
        Capture-->>Host: ImageRef
        Host->>Host: 记录完成结果
    else Esc / 捕获异常 / 显示器拔除
        Host->>Host: 记录取消结果 + reason
    end
    Host->>UI: 请求关闭覆盖层并恢复主窗
    UI-->>Host: 窗口恢复完成
    Host-->>UI: selection_completed 或 selection_cancelled
```

事件发送须在恢复动作完成之后。重复会话 BUSY；临时帧释放；之前运行的脚本保持暂停。

## 监控到动作

```mermaid
flowchart TD
    A[校验临时监控配置] --> B[建立执行上下文 / 立即第一轮]
    B --> C[校验窗口 / 捕获当前帧]
    C --> D{识别结果}
    D -->|未命中| E{等待期限到达?}
    E -->|否| F[按周期等待 / 不积压]
    F --> C
    E -->|是| G{超时策略}
    G -->|有限重试| H[等待退避 / 重置本轮期限]
    H --> C
    G -->|运行失败脚本一次| I[同步调用 / 然后结束]
    G -->|停止或次数耗尽| J[failed timeout]
    D -->|引擎错误| K[failed / 不执行失败动作]
    D -->|命中| L{满足边沿 / 冷却?}
    L -->|否| F
    L -->|是| M[记录 target_id + sample_no + 坐标]
    M --> N[同步成功动作 / 或命中即结束]
    N --> O{成功动作且repeat?}
    O -->|否| P[completed]
    O -->|是且动作成功| Q[冷却 / 新帧]
    Q --> C
    N -->|动作失败| K
```

所有等待/识别/动作都有 stop 旁路：关闭输入闸门 → 取消 token → 释放持有输入 → 丢弃迟到帧 → cancelled。不要把取消画成“进入超时失败脚本”的路径。

## 输入与窗口变化

```mermaid
sequenceDiagram
    participant Lua
    participant Engine
    participant Host
    participant Window
    Lua->>Engine: click_target(id)
    Engine->>Engine: 新帧识别 / 得到 geometry_revision
    Engine->>Host: host_request input_action + lease + action_id
    Host->>Window: 校验身份 / 前台 / 区域 / 几何版本
    alt 一致且未停止
        Host->>Host: SendInput / 更新持有账本
        Host-->>Engine: dispatched
        Engine-->>Lua: true
    else 失焦 / 最小化
        Host->>Host: 关闭当前输入 / 释放按键
        Host-->>Engine: WINDOW_UNAVAILABLE
        Engine->>Engine: paused
    else 窗口消失 / 句柄复用
        Host-->>Engine: WINDOW_NOT_FOUND
        Engine->>Engine: failed
    else 几何版本过期
        Host-->>Engine: STALE_FRAME
        Engine->>Engine: 丢弃结果 / 下次重新识别
    end
```

UI 不收到 target_detected 就自行点击；只有执行器调用输入。已派发到 OS 的事件无法撤回，但停止后不会派发新事件。STALE_FRAME 不是允许无限重试整个脚本的理由。

## 保存与调试

保存：验证字段/外键 → 获取 Repository 锁 → 比对 revision → 写新资产和 generation → fsync/校验 → 原子 current 切换 → 更新内存 → 返回成功/发送 catalog_changed。失败在切换前保留旧指针；切换后查询新 revision 判断已提交。

调试：启动固定源码 hash → 宿主安装 line/count/call/return hooks → Lua 行前命中断点 → 释放输入并暂停 → 获取只读栈/变量 → 用户 step/continue → 校验窗口 → 下一行/调用深度处再次暂停。调试 hook 属于宿主私有状态，不能通过给脚本重新开放 debug 库实现。
