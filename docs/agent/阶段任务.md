## 阶段退出条件

- P0：版本可锁，WinUI 原生主窗、双窗口框选、宿主边界及 OS/Lua/OCR 能力有对应探针证据；不兼容项明确阻塞，不暗自降版本。
- P1：纯脚本和识图动作有端到端路径；输入边界、停止、窗口身份和数据一致性已生效。
- P2：用户要求的监控异常分流、脚本互调、调试、窗口和普通/调试日志体验均可用。
- P3：正式入口与所有窗口均使用 WinUI 3，可在干净 Windows 离线安装/运行/恢复；所有安全输入不变量和性能报告真实可复现。

## Agent 入口

选择一个前置已验证的 TASK-nnn，复制[任务拆解](任务拆解.md)对应分册中的“启动指令”。每个任务完成后检查实际产物、测试退出状态和未覆盖风险，再解除下游依赖。SQLite 实际迁移、外部插件、GPU、跨平台、复杂跨屏和多根执行仍属后续独立决策，不得排除首版已确认的窗口绑定和停止热键。

## 检查入口与依赖权威来源

任务卡的前置为硬依赖；索引同步这些依赖，概要箭头不替代逐项依赖表。不存在以 mock 或 pending 解除硬依赖的例外。依赖未通过时可以准备不依赖该实现的草稿，但不得声明任务验收通过。阶段检查、证据有效期和失败退回按[检查与闭环](检查与闭环.md)执行。P0/P1/P2/P3 使用累计任务门槛；阶段中的 TEST 引用表示相关子场景，整组 TEST 仅由发布全量证据判定。
