# 自动化扩展实施设计 · 坐标、录制与输入

本文定稿后续版本的开发与复验要求。本轮交付设计文档。三种范围均录鼠标、滚轮、键盘和组合键，录制结果只保存为可编辑 Lua。全屏指一台显示器。新录制脚本以窗口或选区比例定位为主。后台仅做窗口模式，在项目自有 Win32 窗口及子控件验证切换到另一前台窗口、目标完全被遮挡和最小化暂停。以下接口名供实施卡落入正式契约时使用。首版任务状态和发布判定由原验收链路管理。

## 从哪些入口接入

| 项目 | 当前可调用的行为 | 本次拟补的能力 |
|---|---|---|
| 定点 | Lua `get_mouse_position()` 读物理坐标，`click_at(x,y)` 按绝对坐标点击，`click_target` 可加固定偏移 | 跟随指针显示物理 X、Y；单击回填，Esc 取消 |
| 范围 | 可枚举、绑定可见窗口，运行上下文可设客户区、屏幕矩形或选定显示器 | 让取点、录制和回放复用同一套范围解析 |
| 动作 | Lua 可提交键、文本、点击、滚动和拖拽；宿主按租约串行派发，保存执行结果 | 将用户明确开始录制后的操作转换为可检查、可保存、可回放的脚本 |
| 后台 | 绑定窗口取像读取前台可见桌面；输入以系统 `SendInput` 派发 | 窗口模式在切换前台、目标完全被遮挡时取像及操作；分别声明后台取像及输入能力 |
| 轨迹 | 移动与拖拽按直线插值；`random`、`wait_random` 与目标偏移可在 Lua 中组合 | 显式选择曲线、点击偏移和延迟参数 |

实现入口见 [Lua 绑定](../../backend/script/api/__init__.py)、[范围类型](../../native/host/src/types/region.rs)、[选择控制器](../../native/host/src/selection/controller.rs)、[窗口身份](../../native/host/src/window/mod.rs)、[输入接线](../../native/host/src/input/wiring.rs)、[派发器](../../native/host/src/input/dispatch.rs)。

## 点选、窗口和坐标

1. 手填 `300,400` 按既有 `screen_physical` 整数点解释。取点也返回同空间的 `Point{x,y}`，允许负数。单像素点不套用框选矩形宽高至少 10 像素的校验。
2. 已确认的交互是在屏幕上随指针显示物理 X、Y，单击即回填发起取点的草稿字段，Esc 直接取消。建议宿主新增 `start_point_pick`、`confirm_point_pick`、`cancel_point_pick`，用同一会话的 `pick_id` 关联。确认读取该次点击的物理点，避免收到回执时鼠标已移动。确认手势由覆盖层接收，不传给目标应用。
3. 回执含 `point`、`space`、`display_id`；选择绑定窗口时另给相对客户区的点、绑定 ID 和几何版本。覆盖层临时取得焦点时用已选窗口身份算坐标；实际输入按所选前台或后台模式检查。取消、Esc、关闭、会话退出、拓扑变化均清理覆盖层与订阅；一次选择只交付一个终态，取消保留原草稿。
4. 运行可用范围沿用 `RunConfig`。窗口模式通过 `list_windows → bind_window` 获取本次绑定，按客户区原点换算；屏幕模式选择 `display_id`，可选 `screen_physical` 矩形。选取客户区内矩形后转成 `window_client_physical`。矩形左闭右开；屏幕截图和文件像素须保留各自空间。
5. 单显示器全屏、限定矩形、绑定窗口共用范围解析。已有的 `allow_exit` 仍按旧脚本定义；新录制默认将回放限制在选择范围。运行时变更范围须新建执行上下文。

### 跨分辨率回放

录制时的参考宽高、锚点类型、相对点及定位策略随动作写入 Lua。当前工作区、窗口句柄、会话 `binding_id` 和活动选区均不随脚本恢复。播放前用户重新指定显示器、区域或窗口。

| 策略 | 建议解析 | 适用场景及失败条件 |
|---|---|---|
| 固定物理点 | 现有 Lua 的绝对点直接交给宿主校验 | 旧脚本及已知固定布局；移到允许区域外时按现有规则拒绝 |
| 锚点内物理偏移 | 当前显示器、矩形或客户区物理原点 + 录制的局部偏移 | 窗口只移动时仍点击同一局部点；尺寸变小、局部点越界时拒绝 |
| 比例定位（新录制默认） | 窗口、选区及所选单屏各轴独立按 `round(p × (newSize−1)/(oldSize−1))` 映射，舍入至最近整数、恰半向上；旧轴长为 1 时取 0 | 跨宽高比仍按两轴比例换算；对于黑边或布局重排，由作者使用固定点或现有识别目标 |
| 识别目标定位 | 使用已保存的 `target_id` 在当前帧重新识别，点击命中中心加指定偏移 | 控件随布局变化时可用；未命中不派发，窗口移动后重新采样 |

显示器负原点先加到局部物理偏移上。WinUI 的局部 DIP 只换算一次；已是物理像素的输入不再乘 DPI。拓扑、窗口身份及几何版本在派发前复查，窗口被销毁后须显式重新绑定。比例定位本身不能判断按钮是否换行或换位。

坐标夹具建议保留下列可手算的向量，使三端实现能定位舍入、边界及原点错误。

| 已知输入 | 应得结果 |
|---|---|
| 参考范围 101×51，点 (50,25)；新范围 201×101，物理原点 (−300,40) | 局部点 (100,50)，最终屏幕点 (−200,90) |
| 同一向量改取参考右下角 (100,50) | 新局部点 (200,100)，严格小于新宽和新高 |
| 源点写成 (101,50)，或新范围已有部分落入显示器间隙 | 拒绝越界数据，在派发前退出该动作并记录原因 |

## 录制、保存与回放

Rust 宿主接受用户显式启动的录制会话，引擎把动作转成可编辑 Lua 草稿，沿用现有脚本验证、保存、修订号和执行入口。现有 WinUI 只补选择范围、启动／结束／取消、查看生成 Lua 和运行结果的最小验证入口。录制及前台回放只将键盘动作归到范围内当前获焦窗口；后台回放明确寻址绑定目标及其子控件。

| 录制范围 | 鼠标事件归属 | 键盘归属 |
|---|---|---|
| 应用窗口 | 只接收绑定窗口客户区内、实际命中目标窗口或其子控件的事件；保存客户区局部点 | 键盘焦点属于目标窗口时接收键和组合键；失焦暂停，其他窗口的键不进入草稿 |
| 框选区域 | 保存相对矩形的点；滚动用事件发生点；拖动起点、路径、终点均须在区域内 | 用户先在框内点击，按实际命中的窗口及其子控件确定归属。首次点击前不收键；失焦或离开范围暂停收键，重新在框内点击才恢复。键盘快捷键的业务效果可能超出框内 |
| 全屏幕 | 用户选择一台显示器，保存相对该屏的点；离开该屏的动作按范围规则处理 | 先点击所选屏的窗口，核对该窗口当前获焦后收键。切换窗口则暂停收键；在该屏内点击新窗口后更新归属。回放前台模式以相应点击后的实际焦点核验，无法建立归属时暂停 |

**事件与可保存性。** 动作序列仅存在录制会话内存中，包含单调时间差、同时间戳的顺序号、锚点及动作参数。忽略录制控制手势及本工具自身注入事件。跨出范围的拖动整笔中止；暂停、失焦或结束时中止未配对的键鼠动作，报告位置并保留之前的完整动作供审阅。原始键流与动作时间线不落盘，保存、取消或关闭后释放。

**键与文字。** 基础键集沿用宿主现有字母、数字、功能键、导航键和修饰键。录制输入法使用期间实际发生的按下／抬起事件；有名称时输出命名键，对名称表未覆盖但有可靠物理键码的按键新增受控扫描码动作，校验扫描码、扩展位和配对关系。未知设备事件标明位置并中止该动作。验收看键序，IME 选择候选后的上屏文字不要求还原。用户可在源码中手写 `type_text`。录制不读取剪贴板或其他窗口文本。[现有键名映射](../../native/host/src/input/action.rs)

**编译与保存。** 单击／双击支持左、中、右键，拖动首批支持左键，另覆盖滚轮、等待、普通键和组合键。滚动先定位，组合键保留实际按下、抬起顺序。能用既有 Lua 动作等价表达时直接生成；其他已纳入的键序用成对的受控按下／释放表示。遇到额外按钮或不能等价表达的动作时中止该动作并标明位置，要求用户确认只保存完整动作。只用现有脚本保存入口写入可编辑 Lua，避免另存录制文件。

相对坐标留到回放时解析。为生成脚本增加受控锚点动作，宿主在同一输入闸门完成几何版本核对、锚点解析与派发。原 API 的参数与绝对坐标语义保持兼容。录制遇到的焦点切换在源码里只保存按动作重新验证的规则；不复用旧 HWND 或按标题强行激活目标。

| 建议接口 | 状态、取消与错误语义 |
|---|---|
| `start_recording(scope,options)` | 显式启动，返回会话内的 `recording_id`；重复请求按原请求 ID 去重，同一桌面新录制与活动输入执行冲突时返回 BUSY |
| `pause_recording` / `resume_recording` | 用户暂停则断开采集，手动恢复时复查身份、范围和焦点。窗口模式失焦时暂停，重新聚焦后由用户恢复；区域／单屏仅丢失键盘归属时仍允许下一次范围内鼠标点击建立归属。暂停时间不计入动作等待 |
| `finish_recording` / `cancel_recording` | 完成时停止采集并冻结草稿，之后由用户保存；取消销毁未保存的会话草稿。两条路径竞争时仅第一个终态有效 |
| `get_recording_state` | 以会话 ID 查询状态、动作数、无法转换的动作位置。事件丢失后查询，不以重复采集恢复；普通诊断日志只记计数、类别和错误 |
| `save_script` / `execute_script` | 用户确认后按修订号保存，再走现有执行控制器与输入租约。回放停止先关闸、释放本执行持有输入；结果未知或部分已派发时终止且不自动重播 |

建议数据量和时长用实测确定上限。超过限额、事件队列溢出或采集器失败要结束采集并标记草稿不完整，显示最后确认位置；进程异常退出时，记录钩子和活动租约应随会话释放。

## 后台兼容模式

现有窗口快照提供客户区物理矩形、可见性、最小化及前台状态；绑定截图要求在前台，输入使用真实桌面键鼠。后续版本新增独立窗口后台模式，现有前台路径继续服务旧配置。[窗口捕获](../../backend/capture/service.py) · [GDI 取像](../../backend/capture/gdi.py) · [Win32 输入](../../native/host/src/input/win32.rs) · [首版范围](../product/产品定义.md)

- 仅在用户显式绑定窗口后允许选择后台模式；显示器全屏、屏幕框选模式请求后台执行时应拒绝。分别声明非前台取像、全遮挡取像及点击、拖动、滚轮、按键、组合键能力。兼容表按窗口类型、权限、状态和动作记录；识别只取目标本身的帧。验证对象为项目自有真实 Win32 窗口和子控件，无第三方应用前置。
- 给捕获端和输入端各注入可选适配器。Win32 后台输入通过消息投递至已绑定窗口或经身份检查的子控件，由接收方事件记录验证实际效果。客户区鼠标消息和需要屏幕坐标的滚轮消息分别换算；键和组合键投递到该目标内的接收控件，不更换系统前台或移动真实指针。捕获、动作派发、[执行控制器](../../backend/script/controller.py)同时读取不可在中途切换的运行模式。旧配置省略该字段时走前台策略；新后台策略只改变对前台身份的要求，继续检查租约、存活、几何、最小化、区域和停止。
- 每次后台调用同时核对绑定身份、适配器能力、动作范围和租约；返回“已提交”的消息可能尚待应用处理。执行结果可通过目标状态观察验证，超时报结果未知，禁止自动重发。后台能力不足时返回不可用原因；切回前台需用户明确选择。
- 对 GPU 自绘、受保护内容、权限级别不兼容等情况分别记录不可用或未知。目标最小化时暂停、释放本执行持有输入并提示还原；用户手动恢复，复查窗口身份、客户区和新帧后继续。捕获失败不能交付旧帧，停止后丢弃迟到结果；对先前已交给目标消息队列的动作记录派发时刻，不能承诺撤回。
- 使用两个独立专窗验证，一边在前台手工输入，另一边后台执行。核对前台焦点、光标、文字和目标窗口实际状态；关闭后新开同标题窗口不得接收旧动作。专窗上五类输入及两种捕获状态全部通过方可交付。其他类型应用按实际探测逐项声明支持。

建议先比较按单一 HWND 创建的 Windows Graphics Capture 会话与由目标绘制客户区的 `PrintWindow`。后者可能同步阻塞，探针应隔离调用并验证关闭能回收。后台消息送达受 Windows 完整性级别限制；发送回执和目标实际处理结果分别记录。用同一组完全遮挡与切换前台的专窗观测选择后端。[窗口捕获项](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createforwindow) · [PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow) · [窗口消息投递](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)

建议专窗使用持续变化的序号、色块和可读回的编辑框；前台观察窗展示另一种颜色。分别在切换前台且目标仍露出、另一个不透明窗口完全覆盖目标两种状态下采集多个连续值，并交叉核对目标内的计数与接收字符。两种状态均须通过；单帧截图或仅收到消息发送成功回执不足以通过。

执行端每次先查已声明能力。仅能取像时可以继续取像；调用未支持的输入动作时在派发前返回明确不可用结果。能力由未知转为可用应有该目标类型和动作的验证记录，不能根据 HWND 存在直接宣称支持。

## 曲线、偏移与浮动延迟

曲线、随机点击偏移、浮动延迟三个选项均默认关闭。产品方已确认在脚本级设置，每个动作可分别覆盖其中任一项，也可显式关闭。点位越界须拒绝。现有 `wait_random` 和手写固定偏移仍保持脚本显式指令的含义。

建议每项单独合并，先取脚本设置，动作未提供时继承，动作显式关闭时忽略该项脚本配置，显式启用时采用该项动作参数。脚本与动作均省略即关闭。运行开始时快照化脚本设置；一个动作的覆盖不泄漏给下一个动作或其他脚本。旧数据缺这些字段时沿用直线移动、原点击和原时序。

单动作覆盖建议采用版本化的选项对象，在新接口中传给同一受控输入代理；省略的字段表示继承，各项以独立开关表达关闭，区间数值为零可以合法表示固定值。保存或执行前拒绝负半径、逆序区间、不适用的参数和超出已有时长限额的动作，返回出错字段。

| 动作属性草案 | 拟实现与核对的语义 |
|---|---|
| 曲线 | 起终点和两个控制点定义三次贝塞尔。先生成实际将派发的离散轨迹，校验全部点及相邻线段与允许区域、显示器空隙的关系，再开始移动；运行中每片复查身份、租约和几何 |
| 点击偏移 | 相对目标中心或显式锚点按给定整数区间采样一次，校验最终点及移动路径。越界拒绝整笔，禁止钳制到边缘、重抽到合法点或退回无偏移点击；同一 action_id 重查不得重新采样或点击 |
| 等待浮动 | 建议首批按用户填写的最小、最大毫秒数采样一次，交给可取消等待；沿用根执行超时。单独配置动作间等待，避免把偏移或延迟暗加给已有脚本 |

测试用固定种子和时钟验证坐标序列与时间界限；真实派发复核目标点、停止时刻、剩余持键和派发次数。安装扩展后，未选择动作配置的同一旧脚本应产生与旧版本相同的动作序列。

## 实施顺序和复验

1. 实施时先在 [02 数据结构](../02-数据结构.md)、[03 IPC](../03-IPC协议.md)、[04 Lua](../04-Lua脚本API.md)、[06 约束](../06-边界条件与约束.md) 纳入带版本的契约和三端向量；正式卡号和硬依赖由主索引统一登记。
2. 复用 TASK-007、TASK-008 的几何与覆盖层，TASK-017 至 TASK-019 的窗口、租约和停止通路，先打通取点、范围解析及确定性回放；再接事件采集、草稿保存与 TASK-020 至 TASK-022 的脚本执行。最后独立验证后台适配器及新轨迹策略，逐项公布可用能力。
3. 按 [验收矩阵](验收与测试.md) 回归旧路径，在同一候选、同一可观测夹具上补下表的新增断言。记录源码基线、介质哈希、Windows build、屏幕布局和缩放、步骤、预期／实际、原始事件及哈希和审查者。

## 交付判据

- 定点、三种录制范围均从最小 WinUI 验证入口走通，并用独立调用方对照同一契约。保存后的 Lua 可以编辑、重开、执行；键盘归属、比例换算、取消和不完整动作的每个用例均有实际观测。
- 前台与后台各走自己的输入适配器；真实专窗能区分捕获失败、派发未确认和动作已被处理。最小化及权限不足时保留原因；未实测的第三方应用按未知报告。
- 曲线用动作空间的两个局部控制点；点击偏移用 X、Y 两个闭整数区间；浮动延迟用毫秒闭区间。缺少显式启用所需参数时拒绝该配置；执行前校验整笔，运行中对几何变化、停止及迟到回执按既有租约清理。
