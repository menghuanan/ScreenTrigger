本文件是待实施测试规格，不是测试结果。WinUI 3 验收适用于全量原生入口及同一候选包，现有旧栈测试结果按各自基线保留。本轮文档静态检查由 `tools/check-docs.ps1` 提供，不替代这些测试。

## 固定数据集与测量方法

模型/算法质量：建议每个声明支持的 OCR 语言至少100张本地标注图片（含数字/标点），另有混合语言、无字、极小字和符号各50张；实际数据集保留 hash、授权来源、字体/尺寸/缩放标签。CER=(替换+删除+插入)/参考字符数，以 NFC Unicode code point 计；每语言单独报告。空参考文本不参与CER除法，另报误报率；未声明覆盖的符号记为不支持，不藏进总平均。

模板/轮廓各至少200正样本、200负样本，含相似干扰物；IoU≥0.5 的唯一匹配算TP，重复框算FP；precision=TP/(TP+FP)，recall=TP/(TP+FN)。阈值在调参子集选，验收子集固定不调；目标 precision≥0.95、recall≥0.90。颜色/几何用合成精确夹具检查边界值（h=359/1、RGB差15/16）和同物体条件组合。

性能建议基准：Windows11 x64、4核8线程、16GiB RAM、无GPU、1920×1080主屏+副屏、ROI 800×600、模板100×100、固定P0模型版本。实际机器型号/CPU/OS build/电源模式/依赖锁/样本hash随报告保存。Win10 与混合DPI另作兼容性验收，不能由Win11单机结果推断。

预热5次后测100次，报告p50/p95/p99/最大值和失败数：

- 预览从桌面帧变化到UI显示 p95≤200ms；坐标位置≤1物理像素误差。
- 停止从Rust收到快捷键/命令到闸门关闭 p95≤200ms；闸门关闭后的新输入事件计数必须为0；持有键清理时长另报。
- 模板1Hz运行至少10分钟，不累积队列；请求5/10/30Hz时记录实际Hz和丢弃tick，不能拿目标Hz作结果。
- OCR 推理 p95建议≤1000ms，单次5s超时；是候选质量门槛，未达需优化或经负责人调整性能承诺，不能伪装已通过。
- 内存预热稳定后进行2小时压力运行，记录总进程树RSS、Lua堆、帧缓存；最后30分钟相对前30分钟稳定基线增长建议≤10%。超过先定位泄漏，不能靠自动重启掩盖。

输入验证使用专门测试窗口和可记录事件的控件，不在用户真实办公数据上跑脚本。停止测试同时采集Rust闸门时间与实际SendInput派发记录，不能只看UI文字变成“已停止”。

## 发布与文档证据

报告应列 build/commit（若有）、命令、环境、数据集、各TEST-nnn结果、失败截图/日志、相关风险。TEST-001–TEST-016 均通过或经产品负责人明确接受的范围调整才能发布；安全输入不变量（停止后无新输入/越界不派发）不能以性能不足豁免。

文档静态检查：本地链接存在、围栏成对、JSON示例可解析、TASK/TEST/A/U/S/D/R 引用存在、v1归档SHA一致。该检查无法证明OCR兼容、Mermaid视觉布局、真实Windows输入或Lua样例执行，报告中应明确区分。
