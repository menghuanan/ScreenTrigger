# Agent 执行约定

本文面向实施 Agent。原生前端的入口、覆盖层和页面清单见[全前端迁移设计](../winui3-migration.md)。先读[产品定义](../product/产品定义.md)、[决策状态](../decisions/技术决策.md)、[阶段任务](阶段任务.md)，再只实现所选任务的依赖已完成部分。

## 任务输入与可修改范围

每项原子任务使用 TASK-001–TASK-029 ID，A01–A10 仅为任务组，输入包括需求 ID、已冻结契约、前置探针、当前文件状态。计划中的代码目录与模块归属见 [01](../01-模块拆分.md)；允许修改对应模块、对应 tests、必要的共享类型和相关文档。新增依赖必须说明用途、精确版本、Python3.13/Windows 支持、许可证、包体影响。

跨模块类型变更先同步 02/03/04/06 与契约测试，再改实现。共享协议不由单个模块私自改名。不得覆盖无关用户修改；实际仓库若尚无 Git，不能假设已在某分支，也不能声称提交/PR 已创建。

## 每个模块的接口使用原则

| 场景 | 允许 | 禁止 |
|---|---|---|
| Vision | Frame + Target 快照 → RecognitionResult | 识别函数直接点击/修改目标库 |
| Script | 调用 Capture/Vision 和 Input 代理 | 直接访问 Win32、文件、网络 |
| Input | 携带 execution_id、lease、action_id 的受控动作 | 裸坐标事件绕过停止、区域/窗口检查 |
| UI | 所有应用界面采用 WinUI 3，通过 C# 宿主客户端调用已注册命令，按状态启用控件 | 直接起 Python、读用户数据文件、收到命中事件自行点击 |
| Repository | expected_revision + 一致提交 | 写失败仍返回成功、损坏文件直接变空库 |
| Debug | paused 快照和宿主 hooks | 向用户脚本开放 debug/任意表达式求值 |
| Plugin | 内置 Provider 接口和工厂 | 提前增加任意插件加载器/联网安装 |

API 输入输出必须遵循单一权威来源：02 数据、03 IPC、04 Lua、06 错误。不要在函数签名中发明同义字段如 position/pos/x 混用；Match 使用 bbox/center。

## 不允许擅自改变的要求

不能改用 Electron、Python3.12、Python/Lua以外脚本 DSL、在线OCR、保存工作区、普通运行实时日志窗，不能把默认1Hz改为固定5Hz上限。不能宣称实现恶意脚本沙箱、所有字符识别、任意后台窗口输入。

若 Python3.13 与候选依赖不兼容，提交 A01 探针结果并标记受影响任务阻塞；继续不依赖该栈的文档/契约工作。用户确认的要求变更必须由用户决定；D01、D02 的当前授权是全部前端转向 WinUI 3。新的产品范围决定和待验证工程参数分别按决策表处理。

## Definition of Done

每任务交付：实现路径、公开契约、实际变更、相关测试结果、尚未支持行为、关联风险状态。必须可复现，不只贴“测试通过”。

- 通过该任务列出的 TEST-nnn；正常、异常、误操作、边界、超时、重试、取消均覆盖相关分支。
- 对任何输入型任务，必须验证停止、按键释放、越界与失焦；仅 happy path 不算完成。
- 单测使用时钟/帧/输入端口替身；真实 OS 行为以隔离测试窗口集成验收，不能只测 mock 证明真实坐标正确。
- UI 普通日志不弹出；错误可理解；键盘可操作与焦点恢复完成手工检查。
- 不残留未完成 TODO 却宣称功能完成，不把示例伪代码当可运行程序。
- 更新需求追踪、相关技术契约及任务状态；归档只读。性能指标附机器/数据集/版本及分位数。

## 回报模板

任务 TASK-nnn / 任务组 Axx；输入需求 Uxx；已修改文件；新增/变更接口；执行的命令和退出状态；TEST-nnn 结果与证据位置；风险/限制；是否达到阶段门槛。未运行的测试明确写“未运行”，没有安装包写“尚无安装包”。

证据必须按[检查与闭环](检查与闭环.md)保存到 reports/raw 和 reports/evidence；使用任务自查入口核验证据后才允许交接。未执行的业务检查保持 NOT_RUN，不得伪造数据。
