# ScreenTrigger 后续版本 · 自动化扩展开发规格

**设计已确认，业务待实施。** 2026-11-26，产品方明确本轮交付 Agent 开发文档，后续 Agent 编码。适配沿用 Windows x64、WinUI 3、Rust 宿主、Python 3.13 和 Lua 5.4。现有 WinUI 提供最小的操作与验证入口，最终用户端美术与独立分包按[后续开发规划](../maintenance/roadmap.md)推进。

## 接手起点

1. 阅读[执行约定](执行约定.md)、[检查与闭环](检查与闭环.md)和[模块所有权](../maintenance/architecture.md)，从项目根运行 `python tools/run_acceptance.py audit --scope baseline`。Windows 的 Python 别名不可用时使用项目的 CPython 3.13 解释器。
2. 以已签核的 **RC16** 为旧行为参照。旧包 SHA-256 为 `2654243c6cb4d0f9c89b1fd609d1e7e6d94829259dda932abd4ca99c71ad0a10`。原审计为 29/29 张卡 VERIFIED，记录在本地 `reports/audits/20261126T022504-714a9f96/summary.md`。原实测、例外和签核见 `reports/TASK-029/RC16-发布前技术验收.md` 与 `reports/TASK-029/RC16-发布签核.md`。任何新基线、新包或新增能力都要产生自己的证据。
3. 按下表找需求，再按“开发顺序”领取最早一张前置满足的卡。产品行为与验收在本页和三份分册中定稿。分册内的拟新增接口属于下一版；接入代码时以[数据结构](../02-数据结构.md)、[IPC](../03-IPC协议.md)、[Lua API](../04-Lua脚本API.md)、[边界约束](../06-边界条件与约束.md)与 [schema](../../schema/README.md)同步生效。产品方授权 Agent 按实测确定内部工程参数，要求在卡内登记取值、依据和复现用例。

## 原始问题与确认的交付

| 原问题 | 本版本的行为与边界 | 实施细节 |
|---|---|---|
| 1．点选 | 手填物理 XY；取点时实时显示物理坐标，单击锁定并回填，Esc 取消。确认手势不得触发目标窗口点击。 | [坐标、录制与输入](自动化扩展-坐标录制与输入.md) |
| 2、3．操作范围与分辨率 | 支持已打开窗口的客户区、屏幕框选区和选定的一台显示器。旧脚本 `click_at` 沿用绝对物理坐标；新录制脚本优先使用窗口或选区比例，单屏按显示器范围映射。布局重排可使用已有识别目标定位。 | [坐标与回放](自动化扩展-坐标录制与输入.md) |
| 4、5、8．模型及发行 | 标准包默认有中英日韩 OCR、ORB 和已有识别算法。发行者按本地清单选模型，用户也可离线增减兼容模型。完整解压后直接启动，程序、用户数据、应用缓存和模型留在解压目录。用户选定的导出 TXT 可在目录外。逐包报告下载大小、展开字节及模型占用。 | [模型、启动与离线发行](自动化扩展-模型启动与离线发行.md) |
| 6．区域文字归档 | 运行前选定 TXT。每次有文字的识别默认按行追加并保留重复，支持覆盖。横排阅读顺序，UTF-8 无 BOM。无字帧保留旧文件；同一次写入的重试只提交一次。 | [文字导出与视觉算法](自动化扩展-文字导出与视觉算法.md) |
| 7．启动性能 | 项目参考机上，从双击标准便携包 EXE 到预置纯 Lua 脚本首句，p95 ≤3 秒；从同一起点到预置脚本拿到第一段 OCR 文字，两套管线各自 p95 ≤10 秒。全新进程、权重未装载；热结果另报。 | [测量方法](自动化扩展-模型启动与离线发行.md) |
| 9．界面范围 | 服务、命令与数据层先行。现有 WinUI 仅补取点、录制、选择文件、模型管理、执行与观察所需的最短路径。新版美术和独立用户端另行设计。 | [前端顺序](../maintenance/roadmap.md) |
| 10．录制 | 窗口、矩形、单屏均可录鼠标、滚轮、键盘及组合键，生成可编辑、可保存、可回放的 Lua。区域和单屏先点击确定键盘归属，输入法按键可录，最终上屏文字不作逐字还原要求。 | [录制与保存](自动化扩展-坐标录制与输入.md) |
| 11．后台模式 | 仅绑定窗口可启用。切到另一前台窗口和目标完全被遮挡两种状态都须取到目标的新帧并完成输入，前台键鼠不受影响；最小化时暂停。以自有 Win32 专窗及其子控件验收，产品方未指定第三方应用。 | [后台方案与专窗用例](自动化扩展-坐标录制与输入.md) |
| 12．动作策略 | 支持贝塞尔移动、随机点击偏移和浮动延迟。三项默认关闭，可按脚本启用，单个动作可覆盖或关闭。任一点越界拒绝整笔动作。 | [轨迹和边界](自动化扩展-坐标录制与输入.md) |
| 13．视觉算法 | ORB 在当前有效区域返回纹理目标的最佳单个实例，留出集精确率 ≥95%、召回率 ≥90%。YOLO 交付可测试的扩展契约与正负向量；实际推理、权重与模型分发属于再后续版本。 | [ORB 与目标检测契约](自动化扩展-文字导出与视觉算法.md) |
| 14．落地 | 旧输入、识别、脚本、安装与用户资料的兼容回归和新能力的专项验收分别留证；全部通过后按新候选哈希交付。 | 下表与[检查入口](检查与闭环.md) |

集成验收至少复演以下三条路径，固定候选包、配置、输入和目标窗口，记录实际观察。

- 从便携包启动，在测试窗口录制点击、拖动、滚轮及组合键，保存并编辑 Lua。移动窗口并改变尺寸后重新绑定回放，按录制比例核对落点。开启单动作曲线再执行，热键停止后记录零新增派发及键释放。
- 在窗口模式选定 OCR 区域和输出 TXT。切换前台，再完全遮挡目标；目标窗口持续显示 A、A、B、A。监控须依次追加四行，覆盖模式最终为 A。前台指针和观察窗事件均可复核；最小化和关闭不得复用旧帧派发动作。
- 新解压并换目录启动标准包。分别用两条 OCR 管线和 ORB 运行预置脚本；移除一条管线后复验纯 Lua、另一条管线及明确的缺模型错误，再从离线介质恢复。归档哈希、字节数、耗时原样本、分位数与网络观察结果。

每张卡完成后提交改动路径、命令、环境、预期与实际、原始记录哈希和审查者。共享契约或模型变化时按影响复验，回归入口见[开发规范](../maintenance/development.md)。只有检查器判定 VERIFIED 才能解除硬依赖；设计本身不计为业务验收。
