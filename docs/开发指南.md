# 开发指南

WinUI 3 开发入口位于 `desktop/ScreenTrigger/ScreenTrigger.csproj`。构建该工程会同时构建 x64 Rust DLL。启动主窗口后可查看实际引擎版本、能力和诊断，停止或重启 Python 子进程。框选探针位于 `tools/probes/windows/SelectionProbe`。各页面的任务归属见[迁移设计](winui3-migration.md)。

## 本地启动

在项目根目录使用 x64 MSVC Rust 工具链、.NET SDK 11.0.100、Windows SDK 10.0.26100.0 和 .NET 10 x64 运行时。NuGet 和 Cargo 依赖分别由项目的 `packages.lock.json` 与 `native/host/Cargo.lock` 锁定。

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: --require-hashes -r manifest/probes-cp313-win-x64.txt
dotnet build desktop/ScreenTrigger/ScreenTrigger.csproj -p:RestoreLockedMode=true
& .\dist\desktop\bin\ScreenTrigger\debug_win-x64\ScreenTrigger.exe
```

主窗通过 Rust 启动 `.venv/Scripts/python.exe`。可用 `SIDECAR_PYTHON` 指定已有的 CPython 3.13 x64 解释器，`SIDECAR_DATA_DIR` 指定隔离测试数据目录，`ST_OCR_MODELS_DIR` 指向含各模型子目录的本地权重库。缺少 OCR 模型时仍可查看引擎状态。开发机的图像依赖快照同时含两个 OpenCV 发行包，实际导入的 `cv2.__version__` 为 4.10.0。发布依赖须在 TASK-027 单独验证。

Windows 开发态会识别 CPython 3.13 标准 venv 启动器。Rust 对照该安装的启动器模板，再按相同的 venv 路径启动底层解释器，使项目环境保持一致，并让宿主在引擎仍存活时收到 stdout 断流。自定义解释器按指定程序启动。[CPython Windows venv 启动实现](https://github.com/python/cpython/blob/3.13/PC/venvlauncher.c)

单独运行框选探针时，确认区域会在参数指定目录下生成一个独立会话，保存选区坐标、预览、最终 PNG 和前后焦点。运行动态计时测试时，需要允许程序操作专用测试窗口并安装 Pillow。

```powershell
dotnet build tools/probes/windows/SelectionProbe/SelectionProbe.csproj -p:RestoreLockedMode=true
& .\dist\selection-probe\bin\SelectionProbe\debug_win-x64\SelectionProbe.exe --output reports/raw/selection
.\.venv\Scripts\python.exe tools/probes/windows/verify_selection.py --exe dist/selection-probe/bin/SelectionProbe/debug_win-x64/SelectionProbe.exe --out reports/raw/selection-test-01
```

测试输出目录须使用新名称。探针可用 `--display` 指定显示设备，回归包含真实指针拖选、计时器像素、渲染后预览的 p95、9×10/10×10、Esc、关窗和捕获故障。在当前机器增加 `--composed-capture` 可单独检查备用实时路径。它让 XAML 内容短暂透明，保留可接收输入的覆盖窗口，等待合成完成后读取新的屏幕像素。早期 Windows build、混合 DPI、负坐标和断网安装进入开发完成后的环境复验。[环境节点排期](agent/deferred-testing.md)

## 开发顺序

1. 读[执行约定](agent/执行约定.md)和[任务卡](agent/任务拆解.md)，先做无硬依赖的 TASK-002 原生窗口及 DPI 探针，并复核 TASK-001 引擎环境。
2. 先验证Python3.13、离线OCR、Lua5.4与Windows捕获/输入关键能力，再冻结依赖与模型。
3. TASK-003、TASK-004 按硬前置建立 C# / XAML 主入口、Rust 原生 DLL 和 Python 子进程，再接通 TASK-005、TASK-006 的协议和共享类型。
4. 按A03–A09实现业务，使用02/03/04/06作契约；A10完成安装与离线验收。

```powershell
py -3.13 --version
rustc --version
cargo --version
dotnet --list-sdks
dotnet --info
```

OCR探针记录 wheel是否存在、CPU推理是否成功、是否偷偷下载模型、已安装语言覆盖；Lua探针验证 `_VERSION`、JSON序列化、line/count hooks及忙循环停止。若不支持Python3.13，记录R01并提出选型问题；不得暗自更换Python版本。

## 迁移目标布局

```text
desktop/ScreenTrigger/       # C# / XAML 页面、窗口、Host 客户端与 Contracts
native/host/src/             # Rust DLL、IPC、输入、热键、窗口与捕获
backend/                     # ipc / capture / vision / targets / storage
                             # script / monitor / debug / config
backend/tests/               # contract / unit / integration
scripts/examples/            # 由真实API验证过的用户示例
reports/                     # 技术探针与验收证据
```

原生项目的 C#、XAML、项目文件与依赖锁纳入源码基线。将生成的 bin/obj 指向已有的 dist 构建输出目录，候选安装包另行绑定哈希。

数据根不放仓库真实用户data；测试使用临时目录和隔离测试窗口。Python核心用类型提示、领域错误、依赖注入的时钟/输入端口；WinUI 的 C# DTO 与 IPC schema 和现有序列化测试向量同步；Rust只开放白名单宿主功能。

## 依赖锁与打包

A01 提供兼容性报告，A02 据此建立 .NET SDK 与 NuGet 锁、Cargo.lock、Python 和模型清单。离线包包含 WinUI/.NET 运行依赖、Rust DLL、受控 Python 和离线模型。按 TASK-027 测量整包大小、内存、启动时间并核对升级后的数据目录。

## 验证入口

实施时运行对应TEST-nnn测试，完整标准见[验收与测试](agent/验收与测试.md)。文档校验可从项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-docs.ps1
```

文档检查、任务证据核验和全局状态汇总可直接执行。建立 WinUI 工程后须单独保存原生构建和交互证据。此处不要求建立分支/提交；版本管理流程由真实仓库配置决定。

检查工具要求 Python 3.13，可直接运行 `python tools/check_docs.py`。执行 `python tools/run_acceptance.py audit --scope baseline` 校验当前文档与账本，执行 `python tools/run_acceptance.py audit --scope release` 查看全局完成度；当前业务未实施时后者应返回 NOT_READY（退出码 1）。工具回归命令为 `python -m unittest discover -s tools/tests -v`，其结果不代表业务验收。

检查流程与命令见[检查与闭环](agent/检查与闭环.md)。

## P0 协议与配置回归

先在仓库根构建主应用。下面的 .NET 控制台工程直接编译应用中的 C# 协议客户端与共享类型，运行结果写入新目录。

```powershell
dotnet build desktop/ScreenTrigger.ContractTests/ScreenTrigger.ContractTests.csproj
$probe = '.\dist\desktop\bin\ScreenTrigger.ContractTests\debug\ScreenTrigger.ContractTests.dll'
dotnet $probe types reports/raw/p0-types
dotnet $probe config reports/raw/p0-config
dotnet $probe protocol reports/raw/p0-protocol
dotnet $probe faults reports/raw/p0-protocol-faults
```

`config` 和 `protocol` 启动真实项目 Python，在独立目录读写配置。`faults` 使用测试进程向真实 Rust 路由器注入乱序、旧会话、超限和连续畸形帧。Windows 上用 `tools/probes/windows/verify-desktop.ps1 -Scenario close_pending` 在专用副窗请求未返回时关窗并停止引擎。需要定位跨窗请求时设置 `ST_IPC_TRACE=1`，stderr 记会话、请求 ID 和命令名。
