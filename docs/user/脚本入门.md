# Lua 脚本入门

以下是设计API示例，当前尚无程序可运行。ID是占位符，请在未来应用的目标库/脚本列表复制真实ID替换。完整签名见[Lua API](../04-Lua脚本API.md)。编写脚本不能读取任意文件或访问网络。

## 纯键鼠脚本

在准备好的测试窗口前台执行，选择“一次”。输入不使用识图能力：

```lua
type_text("Hello ScreenTrigger")
press_key("enter")
wait(0.5)
return {ok = true}
```

想重复三次，在运行设置选“N次，3”，无需再写顶层循环。若同时写for循环和选N次，实际次数会相乘。持续运行模式没有默认一小时上限，需停止按钮/快捷键退出或设置总期限。

## 识别目标并点击

```lua
local found, match = wait_for_target("your-target-id", 15)
if not found then
  log("15秒内未找到，结束本次脚本")
  return {ok = false, reason = "not_found"}
end
log("样本编号: " .. match.sample_no)
-- 重新定位后点击，避免等待返回后窗口移动造成旧坐标误点
local clicked = click_target("your-target-id")
return {ok = clicked}
```

bbox是左上角和宽高；center是中心点。需要查看坐标用 `match.center.x` 与 `match.center.y`。直接click_at只检查当前范围，不验证该点依旧属于原目标。

## 一次检测与多目标

```lua
local found, matches = find_target("your-target-id")
if found then
  log("共找到 " .. #matches .. " 处，首个编号 " .. matches[1].sample_no)
end
return {count = #matches}
```

```lua
local found, by_id = wait_for_all_targets({"target-a", "target-b"}, 10)
if found then
  log("两个目标在同一帧出现")
end
return {ok = found}
```

find_target只检测一次；wait函数会在当前频率下轮询。等待到期返回false，不代表引擎坏了。缺模型等服务故障会抛出错误。

## 读取屏幕文字

先在设置中选择已安装的OCR模型：

```lua
local blocks = ocr()
local texts = json_array({})
for i, block in ipairs(blocks) do
  texts[i] = block.text
  log(block.text .. " (分数 " .. block.confidence .. ")")
end
return {texts = texts}
```

ocr返回实际识别出的文本块，置信度不是正确性保证。对计算前的文本先检查格式：

```lua
local blocks = ocr()
if #blocks == 0 then
  return {ok = false, reason = "no_text"}
end
local value = tonumber(blocks[1].text)
if value == nil then
  return {ok = false, reason = "not_number"}
end
return {ok = true, value = value}
```

## 子脚本计算

创建“计算器”脚本，元数据声明 `a:number`、`b:number` 均必填，保存并复制其ID：

```lua
return {sum = args.a + args.b}
```

父脚本同步调用并接收结果：

```lua
local result = call_script("calculator-script-id", {a = 20, b = 22})
log("结果: " .. result.sum)
return result
```

参数与结果通过JSON复制，父子不共享table。子脚本报错默认让本次执行失败；想处理业务错误可用pcall，见完整API。不要为了重试算术失败而重跑已经发过点击的整个脚本。

## 监控动作脚本

成功动作元数据声明必填 `match:object`；监控设置选该脚本：

```lua
local hit = args.match.matches[1]
log("目标 " .. hit.target_id .. "，样本 " .. hit.sample_no)
return {clicked = click_target(hit.target_id)}
```

超时动作声明必填 `failure:object`：

```lua
log("等待超时，尝试次数 " .. args.failure.attempts, "warning")
beep()
return {handled = true}
```

上述失败动作只在等待超时策略选择“运行脚本”时执行一次。用户停止、模型错误、目标窗口关闭不会触发它。

## 调试与常见错误

用log记录步骤，在关键行加断点，单步查看局部变量。普通运行不显示实时日志面板。`stop_script()`停止整个根执行，子脚本中调用也一样。

返回对象用 `{}`，数组用 `json_array({...})`，显式空值用 `json_null`。不能返回函数、循环table、NaN或多个返回值；例如写 `return {ok=true,data=value}`，不要写 `return true,value`。
