| 读者 | 顺序 | 要回答的问题 |

| 产品负责人、技术负责人 | 产品定义 → 功能规格 → 技术决策 → 阶段任务 | 做什么、为什么做、取舍是什么、何时验收 |

## 维护与冲突处理

用户明确确认的需求优先于设计建议。新增默认值是本轮建议基线，不能表述为用户已确认。决策状态及仍需确认的事项集中在决策记录；不在其他文档复制不同答案。

同一字段以 02 为准；通信以 03 为准；Lua 以 04 为准；错误码以 06 为准。发生冲突时先修订这些来源，再更新引用、示例和测试，不靠“以后再处理”维持双套契约。产品变化必须同步需求追踪、阶段任务和验收用例。

v1 原稿不是当前实施依据。曾经的“50+ API”“170+ 签名”“全部完成”等数量和完成宣称不作为质量证明。函数清单不等于产品规格，代码片段不等于已运行实现。

本轮不安装依赖、不生成业务程序、不声称通过屏幕识别或输入模拟测试。文档静态检查与运行时验证应分别记录。

检查流程与命令见[检查与闭环](agent/检查与闭环.md)。
