# ScreenTrigger

面向 Windows 的本地视觉自动化工具：把屏幕图像标为目标，用 Lua 把识别结果连接到键盘、鼠标操作，也支持不依赖识图的纯脚本循环。

**WinUI 3 开发入口已接通 Rust 与 Python。** 主窗口提供引擎启停、能力状态和诊断。独立框选探针可在动态桌面上选择并保存区域。其他业务页面按任务卡推进。[本地构建与运行](docs/开发指南.md) · [全量迁移设计与任务顺序](docs/winui3-migration.md)

## 解决的问题与适用人群

帮助需要重复操作桌面软件的个人用户、办公自动化人员及桌面测试人员，将“看到特定文字、颜色或形状后执行操作”变成可调试、可停止、可复用的脚本。用户需能理解基础 Lua；首版不提供无代码流程编排。

## 首版功能范围

- 上传图片或框选屏幕，保存带稳定样本编号的目标；支持分组和多条件判断。
- 离线 OCR、模板匹配、相近轮廓匹配、RGB/HSV 颜色检测。
- Lua 脚本、JSON 传参与返回、脚本互调、单步、断点、变量查看。
- 一次、N 次、持续运行、检测目标后停止；区域监控可配置命中动作和未命中策略。
- 选择正在打开的应用窗口，限定识别区域及可选的输入区域；区域只在当前会话使用。
- 全局快捷键、取消与停止；普通运行不弹实时日志窗口，调试时显示日志。

桌面前端统一为 WinUI 3。技术设计采用 C# / XAML、Rust 原生宿主、Python 3.13.x 和 Lua 5.4。PaddleOCR 为离线 OCR 候选实现，依赖和模型组合须先验证。不能承诺任何字体、语言及符号都识别成功。

首版不做云端 OCR、脚本文件/网络访问、恶意代码安全沙箱、插件市场、跨平台、后台向任意窗口可靠注入、规避应用保护机制。SQLite 留接口，实际迁移属于后续版本。
